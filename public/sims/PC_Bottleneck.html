A bottleneck isn't something a CPU or GPU permanently is. It depends on what the system is being asked to do.

Why 4K can shift the balance: 4K has about four times as many pixels per frame as 1080p. In a graphics-heavy workload, that often increases GPU work much more than CPU work, so the bottleneck can shift toward the GPU.

Real performance depends on the game, graphics settings, CPU, GPU, and target frame rate.

The assembly-line idea: The CPU prepares work for the GPU. If the CPU is slower, the GPU spends time waiting. If the GPU is slower, prepared frames pile up in front of it.

This is a workload model, not buying advice. The CPU and GPU numbers are conceptual effective throughput capacities for the selected task, not universal hardware ratings. Real systems overlap more stages and change from scene to scene.

Advanced — formal model and related idea

Simplified two-stage pipeline throughput

Rsystem(T) = min(RCPU(T), RGPU(T))

T is the workload. The system can only finish frames as quickly as the slower stage can handle this particular workload. The animation uses deliberately slowed service times derived from the capacity ratio; it does not emit literal frames per second.

Related, but different: Amdahl's Law

S = 1 / ((1-p) + p/s)

Amdahl's Law describes why speeding up only one fraction of a workload limits total possible speedup. Here, p is the accelerated fraction and s is that fraction's speedup. It is related, but it is not the minimum-throughput equation used by this simulation.

Reality check

Games and creative workloads involve many interacting stages, latency, buffers, drivers, settings, target frame rates, and scene-to-scene variation. This clean two-stage model is for learning the causal pattern: waiting behind a slow producer versus work piling up before a slow consumer.
