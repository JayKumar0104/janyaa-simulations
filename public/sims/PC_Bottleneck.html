Advanced — model, analogy, and Amdahl’s Law

The simplified two-stage throughput model

Rsystem(T) = min(RCPU(T), RGPU(T))

T is the selected workload. The system can only deliver frames as quickly as the slower stage can handle this particular workload. Both CPU and GPU effective capacities depend on T, so changing the workload can change the limiting stage.

Why the assembly line fits

The CPU prepares work and the GPU draws it, like two stations on a line. If one station can handle fewer frames per second, work either piles up before it or the other station waits. As a secondary intuition: widening one part of a restricted flow path does not help much if another restriction still sets the pace. Fluid flow is an analogy here, not a claim of mathematical identity.

Related, but different: Amdahl’s Law

S = 1 / ((1-p) + p/s)

Amdahl’s Law describes the limit on overall speedup when only part of a workload is accelerated: p is the accelerated fraction and s is that fraction’s speedup. It is a related lesson about limited gains, but it is not the minimum-capacity equation used by this demo.

Reality check

Real games overlap many stages and vary by scene, engine, settings, drivers, target frame rate, and hardware. This clean model is for reasoning about bottlenecks, not predicting benchmark results.
