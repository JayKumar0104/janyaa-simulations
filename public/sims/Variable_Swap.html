The swap
that doesn't work.

Almost everyone learning to program reads x = y as "now x and y are joined." They are not. A box can only hold one number, and an assignment does one thing: it copies whatever is in the box on the right, at that exact instant, into the box on the left. Run these four lines one at a time and watch a perfectly sensible-looking swap destroy the very number it was trying to save.

    For the curious — the notional machine

    The mental picture of "what the computer is actually doing while my program runs" has a name in computing-education research: the notional machine. Most early programming bugs are not typing mistakes, they are a wrong notional machine — and the belief that x = y creates a lasting link between two variables is the classic example. The rule the real machine follows is short:

    evaluate the right-hand side to a single value, then store that value in the name on the left

    Both traces in full:

    StepLinexy
    0(start)——
    1x = 55—
    2y = 10510
    3x = y1010
    4y = x1010
    StepLinexytemp
    1x = 55——
    2y = 10510—
    3temp = x5105
    4x = y10105
    5y = temp1055

    Notice that step 3 of the broken version is not "wrong" on its own — it does exactly what it says. The bug is that it is irreversible: the moment x is overwritten, the original 5 no longer exists anywhere in the program, so line 4 has nothing left to copy back.

    The other tricks mentioned in the note above. Python and a few other languages let you write x, y = y, x, which builds both new values before storing either, so no third name is needed. There is also an old arithmetic trick using addition and subtraction, or the exclusive-or operation, that swaps two numbers with no extra storage. Both work, and both hide the rule this page is about, which is why neither is a good place to start.
